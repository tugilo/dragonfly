## 4. 既存基盤の再利用と、本件固有の作業

tugilo が自社運用している Laravel＋React 基盤（認証・権限・監査ログ・Docker 構成・AI API 連携の土台）を確認し、**再利用できるもの**と**本件のために新しく作るもの**を分けた。再利用は「設計と実装の型を流用できる」という意味で、本件向けの実装・テストは必要。

| 区分 | 内容 | 本件での扱い |
|------|------|--------------|
| 再利用できる | ログイン・ユーザー・役割、操作ログ、Docker 構成、バックアップ手順の型 | M1・S の工数を抑える根拠 |
| 再利用できる | AI API 連携の土台: プロバイダ抽象化（OpenAI 実装あり。Anthropic／Google は定義のみ）、**モデル名を設定で固定**、タイムアウト・例外処理、**API キーの暗号化保管（DB・平文を返さない）** | M6A の「設定・版管理」「鍵管理」の下地 |
| 本件固有（新規） | 製本の制約ルール（納期・稼働枠・設備適性・優先度）と候補の絞り込み | M6 |
| 本件固有（新規） | **構造化出力（所定形式）の検証**、実在 ID・件数・業務制約のチェック、**異常時のルール切替** | M6A（既存基盤は自由文生成のみで、検証・切替の仕組みは無い） |
| 本件固有（新規） | **送信項目の許可リスト、得意先等の ID 化と対応表、自由記述の変換・除去、判別不能時の停止** | M6A |
| 本件固有（新規） | プロンプト（業務ルール部分）の管理画面編集と **版管理**、修正例の参照、送信ログ | M6A（既存基盤にプロンプト版管理は無い） |
| 本件固有（新規） | 自然言語指示の解釈（定型範囲）と曖昧時の確認 | M6A の中で範囲が最も動く（§5 A-2） |
| 本件固有（新規） | PDF 解析、生産依頼表入力、CSV 出力、予定表 UI | M2〜M5 |
