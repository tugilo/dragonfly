## 1. 現状の業務フローと課題

### 1.1 注文受付

- **現行公開フォーム:** [https://workerbros.jp/order.php](https://workerbros.jp/order.php)
- **顧客専用フォーム:** URL に顧客IDを付与すると専用画面になる。打合せで例示されたURL: [https://workerbros.jp/order.php?id=3c9gwf23g3](https://workerbros.jp/order.php?id=3c9gwf23g3)（`id=` が顧客ごとの識別子）
- 顧客ごとに **ランダムIDをURLに付与**した注文フォームを共有しているが、URL漏洩時に第三者がアクセスできるセキュリティリスクがある（ログインなしのため、IDを知っていれば誰でも開ける）。
- フォームはコスト削減のためログイン機能を省略して構築したもので、**現在は認証なし**で運用中。
- 画面上は「○○様 専用」と出る一方、メーカー・品番・ボディーカラー等は **手打ち自由入力**であり、誤入力や存在しない品番の入力が頻発し、その都度顧客へ確認連絡が必要。
- フォーム操作が複雑で、注文方法を問い合わせてくる顧客や、めちゃくちゃな入力をする顧客が発生している。
- 現行フォームで確認できる主な入力領域（公開画面ベース）: アイテム名・新規/リピート・納品希望日・完成イメージ画像・入稿データ・加工方法／インク種類・持ち込みボディー・品番行（メーカー／品番／カラー／プリント・刺繍カラー／サイズ／数量）・ネーム加工・OPP個包装・お客様情報・納品先・支払方法・連絡方法。
### 1.2 見積書・請求書作成

- 注文フォーム送信後に PDF が届き、それを目視で確認しながら Excel に手打ちで見積書を作成している。
- Tシャツのボディ部分は自動化できる余地があるが、**印刷位置・加工方法（シルクスクリーン、ラバー等）による料金計算**は組み合わせパターンが無数のため、**今回の自動化対象から除外**する方針。
- 見積書・請求書・納品書は Excel で作成し、マクロで効率化しているが、**二重入力によるミスリスク**は残る。

### 1.3 月次請求管理

- 月次請求の顧客については、発送のたびに見積書 PDF を LINE のアルバム機能（例：「2026年8月分」）に追加し、月初に専用 Excel マクロでフォルダ内ファイルを集計・月次請求書を生成している。
- **個人顧客は都度請求、法人顧客は月次請求**と、請求サイクルが顧客ごとに異なる。

### 1.4 発注・納品

- メーカーへの発注は現在 PDF 目視→手動。主要メーカーの **ユナイテッドアスレ** は CSV 読み込みによる発注機能を提供しているが **未活用**。
- 配送はほぼ **クロネコヤマト** 一本。ヤマトも送り状作成の CSV 読み込みに対応。
- 顧客とのやり取りは基本的に **LINE で完結**（見積書送付・承認・納品・請求）。新規顧客はほぼおらず、リピーターが中心。

### 1.5 ボディーマスタ管理

- 約 **8,000件** のボディーマスタを Excel で独自管理。ユナイテッドアスレの CSV をひな形に、他メーカー分を追加している。
- マスタに未登録の商品が注文されることが多く、その都度手動追加する作業が大きな負担。
- 廃番商品はマスタから削除されておらず、価格改定への対応も遅れがち。

## 2. システム化の方向性（合意・検討内容）

### 2.1 認証・ログイン

- ログイン機能を実装し、顧客ごとのデータ管理と情報セキュリティを確保する。
- **LINEログイン連携**により、LINE公式アカウント経由でアクセスした顧客はログイン操作不要でフォームを利用可能にする案。
- PC ブラウザは ID ログイン、LINE からは LINE ID 紐付けと、入り口は複数持ちながら **同一フォーム画面を共用**する設計。

### 2.2 LINE公式アカウント連携

- LINE公式アカウントのリッチメニューに「Tシャツ注文」ボタンを設置し、タップすると LINE 内ブラウザで注文フォームが立ち上がる仕組みを構築可能。
- 見積書完成後はシステム側から LINE で顧客へ自動送信し、顧客が LINE 上で承認すると制作に移行するフローも将来的に実現できる、という説明。
- **見積書の LINE 送信自体は当面手動のままで問題ない**と粕谷さんが確認。

### 2.3 注文フォームの刷新

- 既存フォームは廃止し、機能を引き継ぎつつ拡張した新フォームを構築する方針で合意。
- ボディのメーカー品番・カラーを **プルダウン＋インクリメンタルサーチ**（入力しながら絞り込み）で選択式にし、誤入力を防止する。
- サイズ・カラー・枚数など複数アイテムを一注文内で同時指定できる現行仕様は維持。
- 加工方法（シルクスクリーン・ラバー等）のプリントカラー選択など細かい指定も継続対応。アパレルブランド顧客のようなこだわりの強いユーザー向けの詳細指定は保持しつつ、初見ユーザーには段階的に項目を表示する設計が望ましい、との認識。
- アイテム名（例：「なんとか中学校バスケ部」）はフォーム入力項目として残し、見積書・請求書のタイトルにも使用する。

### 2.4 見積書・請求書の自動生成

- **ボディ代金部分**については注文フォームのデータから自動で見積書を生成する仕組みを構築する。
- **加工料金**（印刷位置・方法によるパターン）の自動計算は今回スコープ外とし、社内で担当者が加工内容を入力すると見積書が完成する **ハイブリッド方式**を想定。
- 月次請求の集計もシステム内で自動集計できるよう設計する。
- 現行 Excel の見積書・請求書フォーマット（マクロを含む複雑な構成）を参照し、同等以上の機能をウェブシステムで再現する。

### 2.5 メーカー発注 CSV の自動生成

- 注文データからメーカー別に CSV を自動生成するボタンを実装する案（例：ユナイテッドアスレ用・ギルダン用など、メーカーごとのフォーマットに合わせ、1注文から複数出力）。
- ユナイテッドアスレは CSV フォーマット提供済みのため対応しやすい。
- ギルダンなど CSV 非提供メーカーについて、AI／サイトクローリングで品番・カラー・サイズ情報を取得し CSV を生成する方法が **技術的に議論された**（ログイン要否・利用規約等は **未解決・要確認**。確約ではない）。

### 2.6 ヤマト送り状 CSV の自動生成

- 顧客情報からクロネコヤマト向け送り状作成用 CSV を自動出力し、ヤマトのサイトで読み込むことで送り状印刷を効率化する案。

### 2.7 ボディーマスタ管理

- 既存 Excel ボディーマスタ（約8,000件）を CSV でインポートし、データベース化する。
- 管理画面から品番追加・廃番処理・価格改定を容易に行えるようにする。
- マスタに存在しない品番の注文をフォーム上でブロックし、顧客への確認連絡を削減する。

### 2.8 顧客管理・注文履歴

- 顧客管理機能を実装し、リピーターが過去の注文内容を呼び出して枚数変更等の再注文を簡単に行えるようにする。
- **顧客管理・商品（ボディ）管理・注文管理** の3モジュールを基本構成として構築する方針。
