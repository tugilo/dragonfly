### 2.0 解析方式の前提（未確定・最優先確認）

- F-03 の解析は **PDF のテキスト層を読む**方式。AI・OCR ではない
- **受領サンプル（注文書.pdf）は複合機スキャンの画像のみで、この方式では読めない。** メール添付で実際に届く PDF にテキスト層があるかを確認する（数件のサンプル提供を依頼）

### 6.3 自動配置（S-07）— 三層

#### 入力（ルール層）

| 項目 | 出所 | 状態 |
|------|------|------|
| 対象週 | 画面 | 決定 |
| 未配置カード／配置済みカード（固定可） | 予定表 | 決定 |
| 作業場所の稼働枠 | 設定（場所×曜日の時間。既定 8h。塞ぎは 0h） | **実値は未確定** |
| カードの納期 | 決定日 > 配本日 > 希望日 | 案 |
| 作業時間 | カードの値。未入力は「要入力」 | 決定 |
| 優先度 | 高／通常／低（重み 設定） | **実値は未確定** |
| 設備適性 | 判型・仕様ごとに使える場所 | **実値は未確定** |

#### ルール層の処理（案）

1. 納期の早い順に並べる（同じなら優先度、同じなら部数の多い順）
2. 納期の **前営業日** までに終わる候補日を探す（前倒し上限 設定・既定 3営業日）
3. 候補日の中で、適性のある本列（予備でない）で残り稼働枠に収まる場所を候補にする。本列に無ければ予備列
4. どこにも入らないカードは「入らない」として理由付きで一覧に出す（人が判断）
5. 作業時間未入力のカードは配置せず「要入力」に出す
6. **ルール案**（候補の先頭を機械的に採る並べ方）を常に作る。AI が使えないときはこれを提案にする
7. **AI 案の検証:** 形式・実在 ID・件数一致・納期・稼働枠・適性。違反カードは不採用にし、理由を表示

#### AI の処理（案。範囲は §6.4）

- 入力: ルール層の候補集合（ID 化）、業務ルールのプロンプト（管理者編集）、直近の修正例（既定 20 件・4 週。ID 化）
- 出力: 候補の中からの **順番案**と **理由（日本語・1〜2 文）**。所定形式（§6.5）
- 失敗時: タイムアウト（設定。既定 30 秒）、エラー、形式不正 → **ルール案に切替**し「AI 停止中（理由）」を表示。送信ログに記録

#### 出力（人の確認）

- 提案一覧: カード／提案 日付・場所・位置／理由／提案元（AI／ルール）／検証結果
- 予定表の見比べ: 現在と提案を左右に。動くカードを色で（新規 緑、移動 黄、入らない 赤、**AI 不採用 灰**）
- ボタン: 確定（反映して auto_plan_runs に confirmed）／取消／カード単位で採用・不採用

#### 記録（決定）

- 提案 JSON・理由・検証結果・提案元・prompt_version・model_name・ai_used・fallback_reason、確定の有無、確定後 1週間以内の人の入れ替え
- 月1回、「提案どおり」「人が直した」の割合と、よく直されるパターン（得意先・場所・曜日）を簡易表で出す

### 6.4 言葉での指示（F-17。**範囲は未確定**）

| 項目 | 内容 | 状態 |
|------|------|------|
| 入口 | S-06 の指示欄にテキスト入力 → 「変換」 | 案 |

### 6.5 AI 入出力（F-15／F-18。設計方針）

**送る（許可リスト。これ以外は送れない構造にする）**

| 項目 | 形 | 備考 |
|------|----|------|
| 対象週 | 日付範囲 | |
| カード | alias_id、判型コード、部数、納期（日付）、作業時間、優先度、固定フラグ、現在位置（日・場所 ID・順） | 得意先・書名は **alias_id のみ** |
| 作業場所 | 場所 ID、曜日別の残り稼働枠、適性（判型・仕様のコード） | 場所名は ID でよい（社内で復元） |
| 候補 | カードごとの候補日・候補場所（ルール層の結果） | |
| 業務ルール | 管理者が編集したプロンプト業務ルール部分 | 版を記録 |
| 修正例 | 直近 N 件の「提案 → 人がこう直した」（alias 化・理由は定型コードのみ） | 自由記述の理由は送らない |
| 指示 | §6.4 で変換した定型構造 | 原文は送らない |

**送らない:** 氏名・住所・連絡先・金額・書名・PDF 原本・備考原文・修正理由原文・指示原文・API キー・社内パス

**受け取る（所定形式。違反は不採用）**

| 項目 | 形 | 検証 |
|------|----|------|
| 配置案 | カード alias_id ごとに 日付・場所 ID・順 | 実在 alias・候補内・件数一致・納期・稼働枠・適性 |
| 理由 | カードごと 1〜2 文（日本語） | 長さ上限。表示のみに使う |
| 確認要求（指示のとき） | 不明点と選択肢 | 実行しない。人に表示 |

**言い切らないこと:** alias 化しても部数・納期・工数は業務情報。完全匿名・漏えいリスクゼロとは表現しない。送信範囲・修正例の件数・保存期間は国宝社様と合意する。

| 同時編集 | 最後の保存が勝つ。他者の変更は次回表示で通知 |
| **AI タイムアウト・エラー** | ルール案に切替。「AI 停止中（理由）」表示。送信ログに記録 |
| **AI 応答の形式不正・実在しない ID・件数不一致** | 応答全体を不採用 → ルール案。記録 |
| **AI 案の制約違反（納期・稼働枠・適性）** | 該当カードのみ不採用（灰）。他は提示。理由表示 |
| **送信前に判別できない自由記述がある** | 送信を止めて確認。該当項目を除いて送るか、中止かを人が選ぶ |
| **指示が曖昧** | 確認文と選択肢を表示。実行しない |
| **API キー無効・失効** | AI 利用を自動 OFF。管理者に通知。ルールのみで継続 |
| **送信先の証明書検証失敗** | 送信中止。管理者に通知 |

## 10. 検収の考え方（案・合意前。保証しない）

専門家シートの「10回組んで8回以上使えれば合格」は測定単位が未定義のため、並行テスト（計画 4 週間）で測れる指標に置き換えた **案**。**母数・例外・判定者・再試験の方法を現場と合意してから確定**する。合意前に「8割使える」を保証しない。

| # | 対象 | 指標（案） | 母数・条件（要合意） |
|---|------|-----------|----------------------|
| (a) | 注文入力 | 主要1社の PDF で、人が直す項目が 1件あたり平均 2 項目以下。承認 → CSV → 取込が通る | 50 件以上。**テキスト層ありの PDF に限る**。解析不能（画像）は母数から除くか別集計 |
| (b) | 予定表 | 並行テストの各週で、画面で組んだ予定が運用に使えた（紙に戻らない） | 4 週中 4 週。判定は予定組み担当と木村様 |
| (c) | 自動配置（ルール＋AI） | 週次の提案に対し、担当者が確定前に動かしたカードが 2 割以下の週が、4 週中 3 週以上 | 母数は提案カード数。「入らない」「要入力」は除く。AI 停止でルール案だった週は別集計 |
| (d) | 連携 | CSV 取込エラー 0 件（同一ファイル名エラーを除く） | 開発会社の取込口が完成していること |
| (e) | 時間 | 手入力・予定組みの総時間（確認時間を含む）を導入前後で記録 | 検収条件ではなく実測値として報告 |

- (c) は「10回中8回」に近い意味だが同じ指標ではない。AI の精度を単独で保証するものではなく、ルール＋AI＋人の運用として使えるかを見る
- 並行テストが短縮された場合（スケジュール v4）は週数を読み替える
