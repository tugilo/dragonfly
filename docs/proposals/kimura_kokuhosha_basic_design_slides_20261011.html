1. 目的・範囲・原則

基幹は触らない。人が必ず見る。CSV が境界

項目内容
目的注文書PDF と生産依頼表 Excel の手入力、紙の製本作業予定表を、社内 Web に置き換える
範囲注文入力（PDF／手動）、補助DB、CSV 出力、製本作業予定表、自動配置 v1、ユーザー・ログ
範囲外VB 改修、Oracle へのテーブル追加・書き込み、取込プログラム（開発会社）、OCR、得意先ポータル、予定表の印刷・CSV 出力
利用者事務（入力・承認・CSV 出力）、予定組み担当（予定表）、管理者（ユーザー・設定）

原則（6つ）

  1. 基幹は触らない。受注・得意先・注文番号の正は Oracle。補助DB は正にしない
  2. 人が必ず見る。解析結果は人が1件ずつ直して承認。承認前は CSV に出ない
  3. CSV が境界。Oracle へは開発会社の取込プログラムだけが書く
  4. 自動配置は提案。人が確定するまで予定表に反映しない
  5. 段階的に自動化。生産依頼表 Excel は手動入力から
  6. 出さない。予定表の印刷・CSV 出力は作らない

6. 開発会社の確認事項への tugilo 案

通知方法・UPDATE／DELETE・得意先照合

確認事項tugilo 案代替
取込結果の通知方法取込プログラムが 結果ファイル（同名＋_result.csv: 行番号・結果・メッセージ）を既定フォルダに書く。Web が読んで draft に反映結果は VB 画面で見るだけにし、Web は exported 止まり（人が確認）
既存データの UPDATE／DELETE初回は INSERT のみ。承認済みの修正・取消は VB 側で行う運用。Web 側は exported 後の draft を編集不可にする将来、取消 CSV（取消フラグ列）を追加
得意先の照合Web は Oracle 得意先コードを持って出す。コードが無い行は出力前にエラーにする得意先名で出し、取込側で照合

どれも「人が1件ずつ承認してから登録する」という第4回の方針に沿った、いちばん単純な形。開発会社と合わせて確定する。

7. 自動配置 v1（ルール）

提案して、人が確定。記録して v2 に活かす

項目内容
入力対象週、未配置カード、配置済み（固定可）、場所の稼働枠、各カードの納期（決定日／配本日／希望日）、作業時間、優先度、仕様
出力提案（カードごとに日付・場所・位置）と理由（納期／優先度／空き）。現状との差分
確定予定組み担当が S-07 で見て確定。確定まで予定表は変わらない
記録提案と、人が動かした内容を残す。v2 のルール見直しに使う
検証1月の並行テストで現行の手組みと比べ、差の理由を毎週拾う

ルールの順

  1. 納期が近い順
  2. 優先度が高い順
  3. 同じ場所の空き時間に入る順
  4. 予備列は本列が埋まってから
  5. 作業時間が未入力のカードは末尾に置き、要入力の印

条件は 10月の担当者 Zoom で聞き取り、仕様書に落とす。v2（あれば便利）: 前後工程の生産性指標、提案理由の詳細、履歴からの重み調整。
