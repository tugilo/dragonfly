## 3. 「残す」の解釈と選択肢

| 案 | 中身 | 良い点 | 問題点 |
|----|------|--------|--------|
| **A. 今のフォームをそのまま動かし続ける**（並行運用） | order.php は現状のまま。新システムは新規のお客様だけ | お客様は何も変わらない | **一番の困りごと（ログインなし・URLが漏れると誰でも開ける）が残る**。品番の自由入力ミスとPDFからの打ち直しも残る。入口が2つになり、社内は二重管理 |
| **B. 新システムの中に「今と同じ並び・見た目」の画面を作る**（既存準拠の1枚フォーム） | ログインは必須。項目の並びは §2 のまま。品番表だけ「入力しながら候補が出る」形にして、マスタの品番に紐づける | お客様の見た目の変化は小さい。安全性・入力ミス・打ち直しの課題は解決する | 品番表の入力のしかたは少し変わる。画像に位置を書く運用を残すかを決める必要がある |
| **C. B ＋ 新規のお客様向けの案内つきステップ**（2モード） | 常連（既存）＝B、新規＝デモの4ステップ | どちらのお客様にも合う | 画面が2種類になり、作る量・テスト・今後の手直しが増える（→ §5） |

**おすすめ：B を基本にする。** 「残したい」の目的は「既存のお客様が戸惑わないこと」なので、**見た目と並びは今のまま残し、中身（ログイン・品番の選択・データのつながり）だけ新しくする** のが、要望と一番の困りごとの両方を満たす。  
C の新規向けステップは、新規のお客様がほとんどいない（初回ヒアリング §1.4：リピーター中心）ことを考えると、**最初は作らず、必要になったら足す** 候補にできる。  
A は「切り替え期間に限って並行する」場合のみ。期限を決めずに残すと二重管理が続く。

## 4. B 案で「残すもの」と「変わるもの」

| 区分 | 項目 |
|------|------|
| **そのまま残す** | 1枚の縦長フォーム、項目の並び（§2 の 1〜14）、新規デザイン／リピート／無地、納品希望日（最短／指定）、完成イメージ画像（最大4枚）と画像への位置書き込み、加工方法の複数選択と価格表リンク、持ち込みボディー、備考、ネーム加工・OPP、納品先、支払方法、優先連絡方法 |
| **変わる（お客様に見える）** | ログインしてから開く（お客様情報は自動で入る）／品番表のメーカー・品番・カラー・サイズは **入力しながら候補から選ぶ**（マスタにない品番は入れられない）／「注文」か「見積依頼」かを最初に選ぶ（要望②）／過去の注文から「同じ内容で注文」 |
| **変わる（社内だけ）** | 注文がそのまま受注一覧に入る（PDFからの打ち直しがなくなる）、ボディ代の自動見積、帳票・月次請求へのつながり |
