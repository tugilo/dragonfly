## 4. AI を使う部分の作り

### 4-0. 予定表への AI 組み込み案（ルール＋AI。2026-10-14 18:11 JST 追記）

木村さんの意向（予定表で AI を活用したい）を受け、第4回のルールベース v1 を土台に **AI を「提案と説明」の層として重ねる**。ルールは残す（制約の守り手・AI 停止時の代替）。

| 層 | 役割 | 中身 |
|----|------|------|
| **ルール（制約）** | 置けるかどうかを決める | 納期・作業場所の稼働枠・判型×作業の所要時間・場所の適性・優先度 H/N/L。候補を絞り、**制約違反を検知**する（仕様書 §6 の6ルール） |
| **AI（提案・説明・指示）** | 候補の中から順番案を出し、理由を付ける | ①週次の自動配置で **順番案と理由（日本語）** を返す ②担当者の **言葉での指示**（「A社の分を来週に前倒し」「木曜の製本機を空けて」）を受けて組み直す ③（確認事項）メール添付の生産依頼表 Excel／PDF の読み取り補助 |
| **人（確定）** | 画面で動かして確定 | 第4回どおり。AI 案はカード色で区別し、動かした内容を記録 |

- **検証とフォールバック:** AI の出力は必ずルールで検証し、制約違反の案は採用しない。API 停止・遅延・不正な応答のときは **ルール v1 の提案に自動で切り替え**（画面に表示）。
- **モデル:** OpenAI API または Anthropic API（Gemini も可。要判断）。**契約名義は国宝社様**。モデル名を設定で固定し、変更時は過去4週の実データで回帰確認。
- **データ:** 渡すのは 注文ID・判型・数量・納期・所要時間・優先度・場所の空き状況。**得意先名・担当者名は ID に置換**して渡す（必要なら元の名前は社内で復元）。
- **記録:** 提案・採用・人の修正・プロンプトとモデルのバージョンを保存（auto_plan_runs／schedule_moves に列を追加）。月次で「提案どおり／人が直した」割合を出し、プロンプトとルール重みの調整材料にする。
- **見積:** 旧 O4（¥250,000）を **必須へ繰り入れ**。範囲は上表①②まで。③（Excel／PDF 読み取り補助）は旧 O1 と重なるので、入れるなら別途。
- **助成金:** 構築・検証は対象、API 利用料は対象外（No.5・No.8）。申請時の説明（OpenAI／Gemini）と整合する。
