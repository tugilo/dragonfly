1. 結論

作る Web は1つ。人が使う機能は2つ。基幹には手を入れない

機能1　注文入力

注文書PDF をまとめて上げる → 項目ごとの欄に抜き出す → 人が1件ずつ直して承認 → CSV に出す → 既存システム側の取込プログラムが Oracle に入れる。

機能2　製本作業予定表

いま Excel を印刷してペンで組んでいる週次の予定表を、同じ並びの画面に。手で置く操作に加えて 自動配置ボタン（ルールで組む。人が確定）。

第4回で変わった点（3つ）

① Oracle へ直接書き込まない

こちらの DB に仮登録 → CSV 出力 → 既存システムの取込プログラムで Oracle へ。取込プログラムは開発会社が作る（2026-09-29 資料）。

② 自動配置を入れる

AI ではなくルール（納期・作業時間・優先度・場所の空き）で順番を提案し、人が確定する。

③ Excel 生産依頼表は手入力から

メール添付の生産依頼表は、まず手で入力する画面。自動取り込みは段階的に。

3. 機能1　注文入力

PDF → 人が確認 → 承認 → CSV。Oracle へは取込プログラムが入れる

① まとめて上げる注文書PDF をドラッグ＆ドロップ。原本を保存
→
② 解析1件ずつ、項目ごとの欄に抜き出す。信頼度を色で
→
③ 人が直す必ず人が見る。得意先・部数・判型・日付
→
④ 承認こちらの DB に仮番号で登録。「次へ」で次の PDF
→
⑤ CSV 出力承認済みを既定フォルダへ。ファイル名は一意
→
⑥ 取込（既存側）開発会社の取込プログラムが Oracle へ。手動実行

対象

  • 最初は 型の揃った主要1社 の PDF。他社フォーマットは後から足す
  • メール添付の生産依頼表 Excel は 手動入力画面 で同じ DB へ → 同じ CSV へ

やらないこと

  • 100%自動登録。人が1件ずつ承認する
  • Oracle への直接書き込み。Oracle にテーブルも足さない
  • 手書き注文書の OCR
