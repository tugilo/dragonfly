## A. 案件サマリ

竹村裕司さん（ONODE／Cheer Print）から、ASOBISYSTEM 関連の大規模ライブ／イベント告知に向け、公開 WordPress サイトが **短時間のアクセス集中に耐えられるか** を確認してほしい、という依頼。  
**負荷テスト実施の依頼自体は竹村さんから受領済み**（次廣側は着手可）。  
**負荷試験実施枠は確定: 2026-08-08（土）22:00〜24:00 JST**（竹村さん合意）。終了後に報告書を提出する。  
**イベント本番日は 2026-08-18**。それ以前に販売開始の可能性あり。  
加えて、負荷がかかりそうな導線を **別ドメイン静的ページ**（[cheer--print.com/a-expo-fream/](https://cheer--print.com/a-expo-fream/)）へ分離する方針があり、試験対象に含める。  
現状の本サイトは AWS EC2 **t3.micro** 上のログインなし WordPress 公開サイトで、平常時は軽いがピーク耐性は未確認。  
制作会社が AWS／WordPress 実装を担い、次廣は **測る・分析する・判断材料を作る** 側。  
制作会社からは t3.micro のネットワーク帯域を中心にした仮説共有あり（0.064Gbps／約 8MB/s 等）。これは **仮説として検証対象** とし、ネットワーク以外（PHP／DB／CPU／メモリ）も同時に見る。  
予算は税別 **12 万円**。理想構成ではなく **実行可能な短期対策＋負荷試験＋提案** に集中する。  
最終成果は、竹村さんにも制作会社にも「次に何をすべきか」が分かる報告とする。

## B. 目的

### B-1. ビジネス目的

- イベント告知・ローンチ時に Cheer Print サイトが **止まらない／著しく遅れない** 状態に近づけ、機会損失と信頼毀損を防ぐ。
- 竹村さん・制作会社・次廣の三者で、役割と優先順位を共有し、限られた予算と期間で最大の安心を得る。
- 今回を単発で終わらせず、「イベント時アクセス対策・負荷試験」の **再利用可能なモデルケース** にする。

### B-2. 技術目的

- 現状構成（FACT／ASSUMPTION／TO CONFIRM）を整理し、ボトルネック候補を切り分ける。
- ページ容量・想定シナリオ・段階負荷試験により、**どこから遅くなるか／何が限界か** を数字で示す。
- キャッシュ／CDN／一時スペック／静的分離などの候補について、「全部やる」ではなく **効果の高い順に提案** する。

### B-3. 本番イベントに向けた目的

- 本番前に、想定アクセス帯での表示可否を **問題なし／要改善／危険** の3段階で判定する。
- 制作会社が実施すべき対策と、本番当日の監視観点を明確にする。
- 本番直前の強い負荷試験は避け、安全ルールを守ったうえで実測する。

## D. 課題

### D-1. ネットワーク帯域

- t3.micro はバースト型。ベースラインが低いと、大きなページを多数へ同時配信すると完了まで時間が伸びうる。
- 制作会社の「8MB ページ × 100 人 ≈ 100 秒」は **計算例・仮説**。実ページ容量と実測帯域で検証する。
- burst はコントロールしづらく、持続スパイクでは効きにくい可能性。

### D-2. WordPress / PHP

- キャッシュなしだとアクセスごとに PHP が動きやすい。
- ログインなし公開サイトでも、動的生成・プラグイン処理は負荷要因になりうる。

### D-3. DB

- 同一 EC2 上 MySQL の場合、CPU／メモリを Web と奪い合う。
- 一覧・検索・動的ブロックがあると DB が先に苦しくなる可能性。

### D-4. メモリ（約 1GB 想定）

- Apache 同時処理＋PHP＋MySQL が同居すると、スパイクで OOM／スワップが起きやすい。
- メモリ監視が CloudWatch 標準に無い場合、見えずらい。

### D-5. CPU / t3 クレジット

- バースト超過が続くと Standard では性能制限、Unlimited では追加課金の可能性。
- CPU 単独ではなく応答・エラーとセットで見る。

### D-6. CDN / キャッシュ未確認

- 画像・CSS・JS をオリジンから直配信していると、ネットワーク・オリジン負荷が増える。
- ページキャッシュ未導入なら、PHP／DB がピークの主戦場になりやすい。

### D-7. スパイクアクセス

- アリーナ級の一斉誘導（スクリーン QR・MC）は、のべ人数より **短い時間の同時性** が問題。
- 平常時の軽さは、当日安心の根拠にならない。
