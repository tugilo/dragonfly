**1toMany の狙い（資料より）:**  
一人の事業を、全員で深く知る時間。その人の想いや背景にまで踏み込むほど、**自分の仕事にも思いがけない視点が返ってくる**。深く知ることが、確かな信頼の土台になる。  
**聴・問・話:** 背景や想いに耳を傾ける／遠慮より率直な質問／BORでは協業の糸口と実質的な信頼。

**今日のゴール（メンバー向け）:**  
① **導入前→導入後**（防水・動物病院）が残る  
② 「あ、うちのお客様にもあるかも」と思えるところがある  

③ 育てているもの3つ／紹介のあと／DragonFlyチャプター内で組んでいる実例  

**導入で効かせること（話し手メモ・資料準拠）:** 登壇を頼まれた側として、**指示ではなく招待**。お礼→深く知る時間→「似た話があればあとで教えて」→質問歓迎。売り込み感・聞き方の強制は避ける。

**言葉づかい（話し手メモ）:**

| そのまま使う | 言い換える／避ける |
|--------------|-------------------|
| **Lステップ**（商標） | — |
| 転記／二重入力／LINE／フォーム | **PoC**→小さく試す／試し打ち |
| | **SONAE／BCP**→本日割愛（口にしない） |
| | **会の地図**→早めた表現。Religoは **本システム**（1to1・紹介・議事録）で言う |
| | **Before**→導入前は |
| | **Webhook**→口頭では省略（「LINEと裏側をつなぐ」まで） |

| **禁止（カテゴリ侵害）** | **「AI社員」「AI社員派遣」を次廣の仕事として言わない・匂わせない**（＝**横山なおむさん**のカテゴリ）。否定フレーズで「AI社員」を連発しない（語を会場に残す）。AIツール講座にもしない（小中さん領域） |
| **聞かれたとき** | 「AI社員の話なら **横山なおむさん** へ」とパス。次廣は **仕組み構築／自分の司令部** |

### 【04/13】防水・導入前（約50秒）

一つ目。**防水工事**です。

導入前は、手書き日報が請求の足を引っ張っていました。

1. 現場で紙に走り書き → 戻ってから提出  
2. 字も書式もバラバラで、読めない・揃わない  
3. 現場別の時間もコストも、数字にならない  
4. 請求は「たぶんこれくらい」で出すしかない  

紙を書く人、読む人、集計する人、請求する人——**全員に負担が乗っていました。**

### 【05/13】防水・導入後（約50秒）

導入後は、難しいシステムは入れていません。普段の **LINE** から送るだけです。

画面の左が現場の LINE、右が事務所の管理画面です（差し替え枠）。

流れは四つ。  
**LINEで送信 → 揃った日報に → 現場別に集計 → 請求根拠になる。**

読める。一目で分かる。請求の裏づけになる。——事務所で数字が揃う、という状態です。

### 【06/13】防水・Before & After（約40秒）

同じ四人の役割が、少しずつ軽くなります。表を見てください。

| | 導入前 | 導入後 |
|--|--------|--------|
| 日報 | 紙・手書きでバラバラ | **LINEで送る。項目が決まって揃う** |
| 管理者 | 紙をかき集めて転記 | **画面で一目** |
| 請求 | 「たぶん」で書く | **日報の積み上げが根拠** |
| 現場 | 帰社して提出・書き直し | **現場で完結** |

要するに、**日報が集計につながり、請求の根拠になる**ようになった、ということです。
