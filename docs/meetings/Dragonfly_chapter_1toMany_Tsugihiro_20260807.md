## 通し原稿（メインプレゼン・約10分）— 深掘り版

### （0）既出の宣言 — 約40秒

DragonFly の皆さん、こんばんは。AI業務改善システム構築の、次廣です。

**6月23日のメインプレゼンでお話ししたことは、今日は繰り返しません。**  
文系からSEになった話も、増本さんの害虫ブロックの要約も、金の卵・ガチョウの名前も、もう一度やる必要はないと思っています。

今日の1toManyは、**深掘り**です。3つだけ。

1. **現場で、実際に何がどう変わったか**（効果まで数字・事実で）  
2. **6/23では話していない別の事例**  
3. **いま育てている自社製品**（tugical／Religo／SONAE／tugilo-os）と、紹介のあとの打ち順・章内の組み方

では、いきます。

### （1）増本さん案件の裏側 — 約3分

まず、多くの方が覚えている **増本さんの害虫ブロック**。取扱店200社超・500社を目指す話は6/23どおり。今日は **中身と効果** です。

**Before の道具チェーン** は、こうでした。

注文は **Googleフォーム**。中身は **スプレッドシート**。やりとりは **メール**。  
お客様情報・対応記録・作業管理が、**それぞれ別の場所**。同じことを何度も入力。どれが正しい版か分からない。担当がいないと流れが見えない。

いきなり画面は作りませんでした。まず **何を・どの順番で・誰がやっているか** をほどく。転記は要るか、人の判断か、機械でいいか——仕分けが先です。散らばったままきれいな画面を載せると、二重管理が増えて苦しくなるからです。

**導入後の効果（ここを覚えてください）。**

- **転記:** 同じ情報を二度入れなくてよくなった（転記ゼロに近い）  
- **確認:** 手間は体感で **4分の1以下**  
- **経営者:** 知りたい情報がすぐ見られる  
- **スケール:** 取扱店が増えても本部が耐えられる土台（500社規模を見据える）  
- **お金の感覚:** 事務員1人なら月25万・年300万・5年で1,500万の固定費。仕組み側は、たとえば200万円前後でも増員を抑えられれば回収の景色がまったく違う  

増本さん自身の言葉は、**「驚くほど業務効率は良くなり、今後どれだけ取扱店が増えても安心」**、そして **「事務員を増員するよりシステムを作った方が絶対いい」**。価格も相場より安価、ネーミングも一緒、細かな編集もずっと伴走——というのが推薦の中身です。

要するに、便利ツールを売ったのではなく、**伸びる事業を、人が増えなくても回る形にした**。

### （2）6/23で話していない事例 — 約3分

次に、定例会では出していない現場を2つ。**業種は違うのに、壊れ方と効き方は同じ** です。

**① 防水工事業 — LINE日報。**

**Before:** 外国人職人さんも多い現場。日報は手書き。文字が読めない。現場ごとの人件費・材料費・時間が管理者にすぐ来ない。請求の根拠が弱い。給与や原価の話に進むほど、手書きの壁が厚い。

**やったこと:** 難しいシステムは入れず、普段の **LINE** から作業内容・人数・材料を送れる形に。

**効果:**

- 日報が **読める・揃う**（手書き判読のロスが消える）  
- 管理者は現場別の **人件費・材料費・作業時間を一目** で見られる  
- 請求時に **「何にどれだけかかったか」の根拠** が取れる  
- 現場の操作は増やさず、**報告→集計→請求根拠** だけが一本化  

建設・設備・現場系の皆さんには、ここが一番近いと思います。

**② 動物病院 — LINE予約（名古屋・実運用）。**

**Before:** 電話・紙・口頭の予約。受付に負担集中。開院前の並び。午前午後の混み具合が見えにくい。

**やったこと:** カルテ・診療システムは触らない。**予約の入口** と **受付の見える化** だけ。飼い主はLINEでペット・獣医師・日時を選択。空きは○／×。変更・キャンセルもLINE。前日リマインダー自動。電話予約も同じ管理画面へ。

**効果（実績ベース）:**

- **約5年** 運用継続（一過性のPoCではない）  
- 獣医師 **3名** 規模の医院で稼働  
- 予約データ **400件超** でも検索・一覧で回る  
- 飼い主は **並ばず・電話せず** LINEで完結  
- 受付は電話対応中心から **一覧確認** へ。院長は獣医師別に混み具合が見える  

DragonFly では山本葉子さんと動物病院向け案内も組んでいます。サロン・クリニック・店舗で「電話とLINEが混ざっている」なら同じ型。軍司さんのLINE運用の **先** の台帳側、とも言えます。

共通点は一つ。**バラバラ・二重入力・属人化** をほどき、入口は身近な道具、裏側は一本の流れ。

### （3）自社製品・紹介のあと・章内の組み方 — 約3分20秒

最後に、実務の話です。受託で型を作ってきた一方で、いま **自社製品も並行して育てています**。名前だけ先に置きます。

| 製品 | 一言 | 章との接点 |
|------|------|------------|
| **tugical** | 予約・再来店の仕組み（電話とLINEが混ざる店舗向け）。忘れられず戻ってきてもらう導線 | 動物病院LINE予約の型をパッケージ化中。軍司さんの入口とも組める |
| **Religo** | 会の地図。1to1・紹介・議事録を残し、つながりを見える化 | いま皆さんが触れている（または触れ始めている）もの。DragonFly発 |
| **SONAE** | つながる備え。災害時の安否・緊急連絡をLINEで回す | DragonFly BCP 向けに PoC 中。章の備えそのもの |
| **tugilo-os** | 一人会社の「司令部」。判断・進捗・証跡を散らさないOS | お客様に言う「仕組み化」を、自分の開発現場でも実践している基盤 |

本丸の仕事は、いまでも **業務の仕組みを伴走で作ること** です。製品は、同じ思想を **触れやすい入口** にしたもの。小中さんのAI発信とは棲み分けていて、私は **現場に組み込む側／運用の土台側** です。

**紹介のあと、何が起きるか。**

1. **90分の簡単業務効率化診断** — 詰まりを1枚の1本化マップに  
2. **2〜4週間の小さな PoC** — 1箇所だけ直して効くか見る（症状が予約だけなら tugical 候補、全体が絡むなら伴走）  
3. **伴走開発** — 本丸。使いながら直す  

**質の高い紹介** は、現場に症状があり、できれば経営者・決裁者と話せる案件。  
**NGに近い紹介** は、症状なしの「AIに興味がある人」だけ。遠慮なく切ってください。

**章の中で、どう組めるか。**

- **軍司さん** — LINE／Lステップの入口。私は予約・日報・顧客DB・Webhook・tugical側  
- **小中さん** — AIの発信・学び。私は組み込みと tugilo-os 的な運用の土台。ペア可  
- **Web・マーケ** — 問い合わせ増のあとの案件・請求の属人化を裏側セットで  
- **士業・コンサル** — 顧問先の「何から相談すれば」に診断から。SONAE／BCP関心とも接続しうる  
- **BCPまわり** — SONAE の実証・フィードバックを一緒に  

**切り出しは、症状の質問で十分です。**

1. 「社長がいないと回らない状態になっていませんか？」  
2. 「Excel、入力は何回くらい発生していますか？」  
3. 「同じ内容を何度も入れている作業、ありませんか？」  
4. 「特定の人じゃないと分からない業務、ありませんか？」  
5. 「改善が後回しになっている業務は？」  

第三者への一言は、前回どおり。  
👉 **「仕事の流れを整理して、仕組みにしてくれる人がいるよ」**

今日持ち帰ってほしいのは、**効果の解像度** と、**製品名の地図** と、**紹介のあとの打ち順** です。  
深掘りも逆質問も、遠慮なくいきましょう。
