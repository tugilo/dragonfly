## サマリー

定例会の Zoom ブレイクアウトルーム（BOR）の運営手順を、軍司さん作成の引継ぎ資料をもとに **サポートメンバー全員で共有**した。米澤さんと竹村さんが実機で操作し、**作成 → 割り当て → 交換 → 再作成** の一連を体験した。

太田さんが長年の疑問としていた「**2回目のオープンネットワーキングを短時間でどう切り替えているのか**」は、再作成ではなく **「交換」でビジターだけ動かす** ことで解けた。「朝礼中に裏で次のルームを仕込んでいる」という事実も、この日初めて全員に共有された。

来週（10/27）から **複数メンバーが BOR を担当する体制**へ移る。軍司さんは裏側で同じ設定を行い、担当者を支える。

## BOR 運営手順（当日の流れ）

引継ぎ資料の時刻と、講座で出た補足を合わせたもの。資料側の時刻（8:55 作成）より、**朝礼ルームは 8:30 まで**に前倒し。

### 1. 事前準備（朝礼前）

- 画面を **2〜3枚**用意。参加者リスト・部屋割表・当日連絡用の Messenger を常時見える状態に。
- 事前に共有権限をもらう資料: 定例会台本／定例会参加者リスト＆部屋割表／Webマス用 Messenger／DR チャプター当日連絡用 Messenger。
- **30 部屋**を作成。**「参加者によるルーム選択を許可する」を必ずチェック**。自動・手動割り当ては、参加者が意図しないルームに飛ぶため **使わない**。
- オプション: **下2つ（時間制限・カウントダウン）のチェックを外す**（朝礼ルームは時間制限なし）。
- ルーム名: 「朝礼ルーム」「ビジタールーム」に変更。残りは予備。
- **仕様:** ホスト（ルーム作成者）自身は割り当てリストに出ない。「すべてのルームを開く」のあと **自分で入室**する。

### 2. 朝礼中の並行作業

- 朝礼ルームを開いている間に、次のセッション（ON 用）を **「再作成」**で準備する。
- 打席表（部屋割表）を見て、テーブル数（例: 12）ぶんのルームを作成。
- 参加者が集まり次第、1人ずつ割り当てる。ビジターは **9:35 以降**、集まり次第順次。
- メインルームにいなくても割り当て操作はできる。**朝礼に参加しながら裏で作業**できる。

### 3. 9:59 朝礼ルームを閉じる

- プレジデントの「ビジターさんお迎えします」の合図で **「すべてのルームを閉じる」**。ビジタールームのビジターとビジターホストがメインルームに戻る。
- 59分より前には閉じない（チャプターのルール）。
- 閉じた時点で、次の ON 用 12 ルームは **準備済み**の状態になっている。

### 4. オープンネットワーキング 1回目

- オプション: **時間制限あり**。資料は **6分**、講座では **5分**で説明（当日の台本に従う）。カウントダウン **10秒**。
- **「時間切れ時に通知」はチェックしない**（チェックするとビジターホストから苦情が出る）。
- ビジターホストの「行ってらっしゃい」で **「すべてのルームを開く」**。DR メンバーへ「BOR 開きましたので、各自ご移動お願いします」とアナウンス。
- 動画再生中に、割り当てとオプションの最終確認。

### 5. オープンネットワーキング 2回目（最重要・最難関）

- タイマーで自動的に閉じ、全員がメインに戻る。**再作成は不要。**
- 座席表で 1回目・2回目のビジター配置を確認し、**「交換」**でビジターだけ別ルームへ動かす。メンバーは固定。
- 12 テーブルなら交換は **約6回**で終わる。
- **注意:** ルームが開いたまま交換すると参加者が意図せず飛ぶ。**必ずタイマー終了後（閉じた状態）**で操作。
- 欠席者がいると番号がずれる（例: V4 欠席で V5 が 4番の席）。座席表を正に確認。

### 6. ウィークリー後のビジネスブレイクアウト

- 再作成せず、**交換でビジターを 1回目の配置に戻す**。
- オプション: **3分**・カウントダウン 10秒（資料の修正案は 5分。当日の台本に従う）。
- エデュケーション／ウィークリーの間に準備を終える。

### 7. オリエンテーション（最終セッション）

- ビジネスブレイクアウト終了後、**再作成**で **40 部屋**（予備含む）。
- ビジター1名に、オリエンテーションのファシリテーター担当を割り当て（1対1 または 1対2）。参加者リストの「オリエン」列を見る。
- ルーム名: **「はじめの一歩」「なんでも相談室」**（新規入会者がいれば「オリエンテーション」）。
- オプション: **下2つのチェックを外す**（時間制限なし）。
- 台本の「行ってらっしゃい」（約 11:45）で **「すべてのルームを開く」**。ここで BOR 担当の仕事は終わり。

## よくある失敗・注意

| 失敗 | 対策 |
|------|------|
| カウントダウンが 60秒のまま | 次廣が以前やった。ビジターが戻るまで全員が待つ。**最初のルーム作成時に必ず確認** |
| オリエンテーション用ルームに時間制限が残る | 全員が強制退出した前例。下2つのチェックを外す |
| 準備中に「すべてのルームを開く」を誤って押す | 全員が飛ぶ。準備中は **×で閉じておき**、再度開けば作業は続けられる |
| 自分の名前が割り当てリストに出ない | ホストは自分でルームに入る |
| BOR 管理画面を画面共有で見せられない | Zoom の仕様。教える時は口頭＋相手に操作してもらう |
| ルームが開いたまま交換 | 参加者が別ルームへ飛ぶ。閉じてから |
| 座席表と表示名の番号が違う | 参加者が自分で付けた番号が席次表と違うことがある。**席次表を正**に名前を確認・修正 |

## 補足

- **Webマスへの称賛不足:** 横串ミーティングで複数チャプターから「Webマスへの称賛が少なすぎる」との声。次廣はチームメンバーへの称賛を積極的に行う。来週 10/27 朝礼の称賛は **サポートメンバー全員**（定例会後 21時に自主的に集まった姿勢）。
- **太田さんの以前の運用との違い:** 以前は全員を再作成で入れ替えていたため、40名規模で2回転させる非効率な運用だった。「交換」でビジターだけ動かせば大幅に短縮できる。
- **研修の効果:** 次廣「やってみないと分からない」。実機で触ったことで全員が仕組みを理解した。
- **チャプターで一度確認したいこと:** Zoom アカウント設定「ルームが開いている間にブレイクアウトルームを作成・名前変更・削除」が ON か。ON なら、開いたまま次の仕込みの自由度が上がる。
