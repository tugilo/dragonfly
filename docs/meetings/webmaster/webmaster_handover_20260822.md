## アカウント・認証

- Zoom は BNI DragonFly 専用 Gmail に紐づく。グローバル管理アカウント配下のため、一部アプリ・機能が使えない。
- ログインの二段階認証は SMS。いまは倉持さんの電話番号。**9月末〜10月頭** に次廣の番号へ変える。
- メールは Gmail に寄せる方がよい。Xサーバー依存のアドレスは、障害時にロックアウトする。
- Nキャスのマスターアカウントでは、全メンバーのログインパスワードが **6桁数字の平文** で保存されている。倉持さんは「このパスワードは絶対に変えない」運用にしている。開発側（木下さん）へ伝えるべき、という認識。
- マスター系アカウントは複数ある。Webマスター権限の人が管理する。パスワード等は NextCloud の Webマスターフォルダ（閲覧制限済み）へ置く案。**実ファイルの中身は本議事録に書かない。**

## 自動化（Claude Code・NextCloud）

- Zoom レコーディング終了後、Claude Code が動画を切り出して NextCloud へ上げる Pipeline が動いている。対象はメインプレゼン・エデュケーション・ウィークリー・シェアストーリー。
- Facebook グループへの投稿だけ手動。それ以外はほぼ自動。
- NextCloud はオープンソース。Xサーバー上。容量 **500GB**、使用 **約140GB**（バックアップ含む）。昨日の「名称・容量は今夜確認」はこれで埋まった。
- 引継ぎ案: サーバーの APIキーを渡し、Markdown で引継ぎ情報を置けば、倉持さん不在でも自動化を続けられる可能性がある。
- Xサーバー管理画面から APIキーを発行（無期限または180日）すると、Claude Code がサブドメイン作成を含むサーバー操作を実行できる。
- Canva は MCP 連携で自動生成済み。背景切り替えも自動で対応できる、との説明。
- レコーディング切り忘れ（過去に28時間録画になった例）対策として、文字起こしも NextCloud に置くと管理精度が上がる、という話。

- メンバーシップ委員会フォルダは委員 **5名のみ**。次期委員への権限移譲は **9月末の定例会後**。
- 過去メンバーリスト（6期〜）をマスターシートとして蓄積。各期末スナップショットもあり、「あの時期の役職」を遡れる。
- 全メンバー分のアカウントは作ってあるが、活用は低い。毎回ログインの手間を減らすため、ログインなしでも触れる設定にしている。
- メンバー追加時の NextCloud アカウント発行と初期パスワード通知は、いま倉持さん。本来はメンバーシップまたはバイスだが、ルールは無い。

## Nキャス（旧→新）

- 旧（9系）から新（110系）へ、**10期終了前（9月末目安）** に移す。
- 旧のチャプター情報欄に「こちらではありません、新Nキャスへ」と大きな赤字 HTML で告知する。

## ブレイクアウトルーム

- 通常: 朝礼時に約30室を事前作成し、台本の BOR 番号を見ながら一人ずつ手動割り当て。ビジターだけ2回入れ替え。
- **ブレイクアウトリザベーション**（倉持さん開発の Zoom 連携アプリ）: パターンを保存し、本番直前に Zoom へ反映。BOD（50〜60名）では30室を約15秒で割り当てた実績。
- このアプリは **個人 Zoom（共同ホスト）** でのみ動く。チャプター Zoom はグローバル管理下でアプリを入れられない。
- 設定: 「時間切れ時に自分に通知」をオフにしないと手動操作が要る。「参加者によるルーム選択」と「メインセッションへの戻り許可」は必須。
- Zoom 本体の CSV 自動割り当ては、BNI アカウントではグローバル管理者の許可が要り、使えない。
- 担当の **軍司 敦哉** さんへのレクチャーが残る。
