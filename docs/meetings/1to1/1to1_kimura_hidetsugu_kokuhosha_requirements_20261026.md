## 1. 読取方式の判断

| 観点 | 事実 | 判断 |
|------|------|------|
| PDF の中身 | サンプルは **画像のみ（スキャン）**。テキスト層なし。ただし **印刷した注文書をスキャンしたものの可能性**あり | サンプルだけでは判断しない。**文字 PDF なら文字抽出、画像なら OCR の両対応**で作り、実物で主方式を確定 |
| フォーマット | 出版社ポータルから DL する「製本注文書」で **様式固定**（枠・項目位置が同じ）。1 PDF に複数ページ（サンプルは 22/22） | どちらの方式でも **様式テンプレート**で項目を切り出せる。AI（LLM）は不要 |
| 文字の種類 | 印字（明朝・ゴシック）＋ 一部手書き（右下の日付・サイン）＋ 付箋（黄色の塗り） | 印字部分のみ読取対象。手書き・付箋は対象外（人が画面で入力） |
| 精度の要 | 部数・丁数・日付・コード類の **数字** | 数字は確認必須項目にし、桁・範囲・日付妥当性をチェック。人が 1 件ずつ承認（第2回からの原則） |
| 実物の確認 | ポータル DL の PDF が **文字 PDF の可能性**が十分ある（サンプルは印刷→スキャン経由かもしれない） | **DL したままの PDF を数件**もらって確認（印刷・スキャンを経ていないもの）。文字 PDF なら OCR 不要でさらに単純 |

**方式（案）:** 文字抽出（文字 PDF・位置情報つき）または 社内サーバーで OCR（画像。日本語対応のオープンソース OCR エンジン。外部送信なし）→ ページ分割 → 様式テンプレートで項目切り出し → 正規化（全角半角・日付・数値）→ 画面に表示 → 人が確認・承認。**AI・外部 API は使わない**（第5回決定と整合）。

**v3 見積への影響:** M2「注文入力（PDF）」はテキスト層前提で ¥500,000。OCR にも対応すると、OCR エンジン組み込み・テンプレート作成・精度確認（サンプル 50 件以上）の作業が加わる。**金額は正式見積で提示**（本書では置かない）。

## 4. 設計への反映（M2 注文入力）

1. **ページ分割:** 1 PDF 複数ページ → H4「n/N」とヘッダー枠の検出で 1 件ずつに分割。画面で「次へ」で切替（第5回要件）。
2. **文字抽出／OCR＋様式テンプレート:** 様式固定を前提に、項目ごとの矩形を定義。読取エンジンは文字 PDF・画像で切り替え。出版社（ポータル）ごとにテンプレートを持つ（最初は主要 1 社）。
3. **正規化と検証:** 全角→半角、カンマ除去、日付形式、数値範囲、判型の寸法一致（112×173 ↔ 新書判）。
4. **コード変換表:** 部品名→種別コード、印刷所名→印刷所コード、加工所名→加工所コード、シリーズ略号→シリーズコード。**管理画面で編集**（予定表の条件と同じ思想）。
5. **PDF に無い項目の入力:** 製本日（カレンダー）、工場（予定表の結果で埋まる）、部・部署・担当者、発売日、丁合人数など → 既定値＋手入力。
6. **再発行の突合:** 発注 No.（H1）＋品目コード（H7）で既存と突合。差分を項目単位で表示。自動上書きしない（第5回決定）。
7. **信頼度と確認:** OCR 信頼度が低い項目・数字項目は色で強調し、承認前に必ず目視。重版（刷数 ≥2）は前回データとの差分のみ確認（現行の「コード呼び出し」運用に合わせる）。
