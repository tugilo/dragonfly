### 関谷さん：伴走型システム開発

**業界の課題として挙げた3つ**

- リリース後のフォローが足りない（作って終わり）。
- 料金がわかりにくい（「一式○百万円」の見積）。
- SESや多重下請けの構造。

**AIEのやり方**

- **アジャイルとスパイラルの組み合わせ。** 要件定義と設計のあと、予算の範囲で「開発 → テスト → 納品」を繰り返す。
- **段階的に広げる。** 例：1,000万円規模のシステムを、初年度は300万円分から始め、3〜5年かけて完成させる。
- **工数表を必ず出す。** すべての案件で、設計・開発・試験の工数と単価を示し、画面ごとの金額まで出す。
- **自社内で開発を完結させる**（多重下請けにしない）。

**料金の3パターン**

1. 工数表にもとづく見積（従来型）
2. ROI・ベネフィットにもとづく見積（効率化・人件費削減・売上向上を数字にする）
3. 月額固定（月150万円でAIエンジニアを1名まるごと。日単価にすると約75,000円）

**AIの使い方**

- お客様がAIを使いたいか、セキュリティ要件はどうかを聞いたうえで、松竹梅の形で提案する。
- 行政案件など機密性の高いものは、AIを使わない従来型でも開発する。

**実績**

- ホームページ制作は、士業（税理士・弁護士・行政書士など）が約5割、一般企業が約5割。
- システム開発は年10案件ほどのペースで、8期で約80案件。
- 最大の案件は、鹿児島県徳之島の2町との直接取引（役場の基幹業務システム、町営バンガローの管理システム）。
- 最小の案件は、2〜3名規模の個人サロン向けシステム（70〜80万円）。数千万円規模まで対応している。

### 次廣：AI業務改善システム構築

- **コーディングはAIに任せる。** 設計は自分で行い、コーディングはほぼAIに任せる。これで、以前は受けられなかった領域にも広げている。
- **ワークフローを優先する。** 「システムに人が合わせる」のではなく、「いまの業務の流れにシステムを合わせる」。
- **伴走する。** 納品後も改善を続ける。手は離れないが満足度が高く、口コミで案件が広がる。
- **見積をROIベースに変えた。** 工数ベースから切り替えて1〜2年。単価が大きく上がった。
- **LINE連携。** Lステップの API 連携が出る前から、自前で LINE とシステムをつないできた。日報提出システムなども構築した。
- **対応範囲。** Webシステム、アプリ開発、PM（200人規模のプロジェクト経験あり）。会計システム以外はほぼ対応できる。
- **主なお客様。** 建設業・製造業のDX案件が多い。
